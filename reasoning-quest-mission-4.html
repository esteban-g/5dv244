The important idea is that the robot does not simply "know" the goal.

It needs a sequence of actions that transforms the initial state into a state satisfying the goal.

⚙️ Representing Actions in ASP

An action can be represented as an ASP atom:

move(robot, A, B).
move(robot, B, C).
move(robot, C, D).

We can also represent the state of the world:

at(robot, A).
goal(D).

A planning problem therefore contains at least three important ingredients:

  • an initial state
  • possible actions
  • a goal state

🧠 From State to State

Planning becomes interesting because actions change the state of the world.

Suppose:

at(robot,A).

move(A,B).

After executing the action, what should hold?

The conceptual point is important: actions produce transitions between states.

What does this constraint mean?

⚙️ The ASP Planner

A simplified planning formulation might look like this:

% Initial state
at(robot,A).

% Possible actions
1 { action(move(A,B),T) : step(T) } 1.

% State transition
at(robot,B,T+1) :-
    action(move(A,B),T).

% Goal constraint
:- not at(robot,D,last).

The exact encoding of a planning problem can become considerably more sophisticated, but the conceptual structure is the same:

  1. describe the initial state;
  2. describe possible actions;
  3. describe how actions change states;
  4. constrain the solutions;
  5. require the goal to be satisfied.

🎓 Mission Reflection

You have now crossed an important boundary in symbolic AI.

In the previous mission, the question was:

"What follows from what I know?"

In this mission, the question became:

"What should I do to achieve my goal?"

This distinction is central to automated planning.

An ASP planner can represent possible actions, their effects, constraints, and desired goals, and use answer-set solving to search for solutions.

In other words:

Knowledge → Actions → States → Goal
